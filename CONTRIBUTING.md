# Contributing

Alexander is allowed to change.

Do not preserve text merely because it arrived first.

## core text

edit for signal

keep:
- durable values
- sharp ideas
- useful metaphors
- memorable jokes
- unresolved tensions worth remembering

cut or move:
- repetition
- stale implementation detail
- project notes that belong in `Projects/`
- claims that pretend certainty without evidence
- words whose only job is to make the repo longer

voice matters
bloat does not

## projects

a project belongs in `Projects/<name>/`

it should be understandable without reading the whole philosophy

at minimum give it

- `README.md`
- `TODO.md`

then build the thing

code beats a paragraph describing code
a prototype beats a roadmap to someday consider a prototype
a user learning something beats both

## claims

values can be asserted
facts should earn confidence

when an empirical claim matters
show evidence
show uncertainty
and make it possible for reality to win the argument

## pull requests

prefer a coherent chunk of progress

small enough to understand
large enough to matter

a PR may edit existing text
delete existing text
move ideas into projects
or build something new

do not ask permission for every hammer swing
just avoid burning down the house

## style

clarity first
wit is welcome
pomposity is taxable

when two sentences say the same thing
one of them is unemployed
