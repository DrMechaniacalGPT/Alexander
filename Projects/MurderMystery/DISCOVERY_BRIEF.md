# Discovery work brief

## Outcome

Produce an evidence-backed decision on whether Alexander should build a sellable three-hour, in-person murder mystery party, for which buyer and player experience, and which concept should be prototyped first. The result is a concise project README and decision memo supported by inspectable source records and completed M01–M06 task syntheses. A polished theme pitch alone is not completion.

## Authorized work

Continue across seller discovery, buyer/player feedback, YouTube and community discussion, game-format analysis, delivery economics, and concept comparison without asking the owner to assign each next step. Use read-only parallel agents for independent searches when useful; one integrating agent resolves duplicates and contradictions. Commit evidence and open focused PRs at checkpoints. An open PR does not stop other independent research.

Follow the shared project guidance, the market method, and the task board. Improve the method in a visible diff if evidence shows a flaw; never silently relax a completion test. Use current primary seller and platform pages for offers and prices; keep marketplace reviews, online anecdotes, vendor claims, and observed game behavior distinct. Search for exceptions to preferred hypotheses, including paper-only, app-first, fixed-culprit, random-culprit, scripted, and freeform games.

Do not declare the catalog exhaustive because it reaches a numeric quota. Log search windows and exclusions; if successive broad batches continue finding new seller types, record non-saturation and keep going within the work budget. Separate lifetime shop counts from annual title sales, original currency from converted currency, gross from contribution, and scenario inputs from measurements.

For candidate selection, include The Immortality Club as one hypothesis. Use host and player personas to attack concepts, then seek real customer evidence. Do not claim that agent roleplay proves demand or that a simulated game proves delight.

## Verification

The discovery decision must link to:

1. A seller/product matrix with dated direct sources, multiple formats, and known coverage gaps.
2. A stratified review sample that distinguishes the host's preparation from players' evening, plus contrary examples.
3. Search records and synthesis for YouTube, Reddit/communities, and inspectable game rules/previews.
4. A model of price, unit demand scenarios, fees, refunds, support, acquisition, labor, and break-even units, with all inputs traceable.
5. A broad concept set, explicit selection criteria, and the strongest case against the favored concept.

Report confidence and remaining uncertainty. If human interviews or paid tests are unavailable, state exactly what can be decided from desk research and what awaits those tests.

## Stop conditions

Stop at a genuine discovery gate when the evidence supports a reviewable proceed/revise/stop recommendation, or when a material dependency cannot be resolved with available tools. Do not stop merely because a plan, task list, source count, commit, or PR exists. Do not spend money, contact prospective players, publish a product, or claim playtest results without actual authorization and access. If a task environment loses internet or repo access, report the attempted work and the precise blocker.

This brief specifies a long-running assignment; placing it in GitHub does not start an agent. Use it as the prompt/context for a configured Codex cloud task or supported Goal session with access to the repo and research sources.
